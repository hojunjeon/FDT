# FDT 리뷰 보완 계약 (2026-09-05)

`03_FDT_설계.md`의 구조와 읽기 전용 원칙을 유지한다. 아래 내용은 리뷰에서 발견한 경계 오류를 수정하는 추가 계약이며, 충돌하는 기존 설명에는 이 문서를 우선 적용한다.

## 1. 계산 및 평가

- 목표 계획의 정기 수입은 시뮬레이터의 `_next_income` 일정을 재사용한다. 31일 급여는 2월 말일로 보정하더라도 3월에는 31일로 복구한다. 다음 수입일이 없는 경우 정기 수입을 임의로 만들어 넣지 않는다.
- 목표일은 기준일 이후 365일 이내로 제한한다. 목표 계획의 `feasible`은 총액·봉투 하한 기준의 결과이며 중간 결제일 안전성이나 달성 확률을 보장하지 않는다.
- 재배분 제안의 이동 합계는 실제 유연 봉투의 여유 공급량을 넘지 않는다.
- 동일 ID·동일 내용의 거래는 한 번만 인입한다. 동일 ID·다른 내용은 순서를 임의 선택하지 않고 오류로 처리한다. 이는 단일 스냅샷의 중복 방어이며, 실제 금융망 상태 변경·늦은 취소의 이력 관리는 별도 과제다.
- 캘리브레이션 합격은 표본 30개 이상, 0/1 관측 모두 존재, 관측이 있는 각 구간에 15개 이상의 표본이 있어야 가능하다. 부족한 표본은 `insufficient_data`, 빈 표본은 `blocked`로 보고한다. 겹치는 평가 기간의 통계적 독립성을 보장하는 기준은 아니다.

## 2. 에이전트 및 웹 경계

- 실행 성공 여부(`status`)와 설명 충실도(`faithful`)를 분리한다. 오류 결과를 성공형 코칭으로 바꾸지 않는다.
- 필수 금액·날짜 누락, 소수 기간, 범위 밖 날짜를 0이나 60일로 조용히 변경하지 않는다. 금액은 0~1조 원의 정수 원으로 제한한다.
- 일반 대화는 금융 계산을 강제하지 않는다. 기존 명시적 금융 요청의 도구는 유지한다. 미구현 정책 도구는 LLM 활성 목록에서 숨기되 기존 직접 호출에는 미지원 결과를 반환한다.
- 로컬 로그 조회는 기본 비활성화한다. 명시적으로 활성화한 경우에만 조회하며, 공유 배포용 인증·사용자별 권한을 대신하지 않는다.
- 웹 세션에 유휴 만료·수량 제한을 두고, 전역 세션 잠금을 잡은 상태에서 개별 세션 잠금을 기다리지 않는다.
- 화면은 세션·화면 버전이 다른 늦은 응답을 버린다. 결측 금액·확률은 0이 아니라 `자료 없음`이다.
- 로그는 파일 수정 시각이 아닌 레코드의 실제 시간으로 병합한다. 같은 시간일 때의 순서는 결정론적으로 유지한다.

## 3. 검증 및 범위

- 변경마다 Python 테스트와 JavaScript 회귀 테스트를 실행한다. 실제 Ollama 추론, Windows 실행기, 실제 금융망은 별도 검증이 필요하다.
- 전체 백테스트 통과, 교정된 위험 확률, 자연어 의미 충실도까지 보장했다는 의미로 테스트 성공을 해석하지 않는다.
- 후속 설계 과제: 필드·단위별 사실 계약, 관측 시각을 포함한 과거 상태 재구성, 경로별 공통 난수, 목표 계획 재시뮬레이션, 복수 계좌별 현금 흐름, 카드 재시도 정책 통일, 실제 서비스 인증·권한.
